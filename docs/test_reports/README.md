# Test Reports Documentation

This document provides an overview of the test report files and templates used for testing the AWS EKS Terraform module. The reports document both unit tests and functional tests performed on the module.

## Report Files Structure

```
test/
├── test_report_template.md         # Base template for all test reports
├── results/                        # Directory containing generated test reports
│   ├── test_report_YYYYMMDD_HHMMSS.md    # Actual test reports with timestamps
│   └── sample_mock_test_report.md        # Sample mock test report
```

## Report Types

### 1. Test Report Template

**File:** `test_report_template.md`

**Purpose:** Serves as the base template for all test reports. Contains placeholders that are replaced with actual values during test execution.

**Structure:**
- Test Summary (date, tester, versions)
- Environment Details (AWS region, account, VPC, subnets)
- Basic Test Results (cluster creation, node groups, etc.)
- Advanced Test Results (IPv6, private endpoints, etc.)
- Performance Metrics
- Test Coverage
- Known Limitations
- Conclusion and Next Steps
- Appendices (test logs, verification commands)

**Usage:**
- Used by `generate_report.sh` to create new test reports
- Placeholders like `[DATE]`, `[TERRAFORM VERSION]` are replaced with actual values

### 2. Basic Test Reports

**File Pattern:** `results/test_report_YYYYMMDD_HHMMSS.md`

**Purpose:** Documents the results of running basic tests that validate core functionality of the EKS module.

**Generated By:** `run_tests.sh basic`

**Key Sections:**
- Basic Cluster Creation
- Node Groups
- Fargate Profiles
- OIDC Provider
- Security Groups

**Example Content:**
```markdown
## Test Results

### 1. Basic Cluster Creation

| Test Case | Status | Notes |
|-----------|--------|-------|
| Cluster Creation | ✅ | Created in 5m 23s |
| Cluster ARN Validation | ✅ | ARN format verified |
| Cluster Endpoint Validation | ✅ | Endpoint accessible |
| Cluster Version Validation | ✅ | Version 1.29 verified |
```

## Report Generation Process

1. **Template Selection:**
   - Basic/Advanced tests use `test_report_template.md`
   - Mock tests use the same template but with mock-specific placeholders

2. **Test Execution:**
   - Tests are run using the appropriate script (`run_tests.sh` or `run_mock_tests.sh`)
   - Test results are collected during execution

3. **Report Generation:**
   - Template is copied to the results directory with a timestamp
   - Placeholders are replaced with actual values
   - Test results are inserted into the appropriate sections

4. **Report Storage:**
   - All reports are stored in the `results/` directory
   - Naming convention includes timestamp for uniqueness

## Test Types

The test reports document two main types of tests:

### Unit Tests (Mock Tests)

Unit tests validate the module configuration without creating actual AWS resources. These tests:

- Use a mocked AWS provider
- Run the `plan` command instead of `apply`
- Validate configuration syntax and structure
- Check resource definitions, inputs, and outputs
- Run quickly and don't incur AWS costs

Unit test reports typically include:
- Configuration validation results
- Syntax validation results
- Resource definition validation
- Input/output validation

### Functional Tests

Functional tests create actual AWS resources and validate their behavior. These tests:

- Use a real AWS provider with credentials
- Run the `apply` command to create resources
- Validate that resources are created correctly
- Test interactions between components
- Verify real-world behavior

Functional test reports typically include:
- Resource creation results
- Configuration validation
- Integration test results
- Performance metrics
- Cleanup validation

## Customizing Reports

To customize the test report template:

1. Edit `test_report_template.md` to add or modify sections
2. Update the report generation scripts to handle new placeholders
3. Modify test scripts to collect additional data for the reports

## Best Practices

1. **Consistent Naming:** Follow the established naming conventions for reports
2. **Detailed Notes:** Include detailed notes for test failures
3. **Regular Cleanup:** Periodically clean up old reports to save space
4. **Version Control:** Consider storing important reports in version control
5. **Comprehensive Coverage:** Ensure reports cover all critical module components
6. **Separate Unit and Functional Tests:** Clearly distinguish between unit test reports and functional test reports
7. **Include Both Test Types:** Run both unit and functional tests for comprehensive validation
